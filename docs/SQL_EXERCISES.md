# SQL-задачи по JazzLMS

Цель — освоить SQL на реальных данных учебной платформы: SELECT, WHERE, ORDER BY, GROUP BY, HAVING,
JOIN (INNER / LEFT / self), подзапросы, CTE, оконные функции, JSONB, транзакции.

**Как работать.** Подключитесь к PostgreSQL (см. [SETUP.md, раздел 7](SETUP.md#7-подключиться-к-базам-данных)).
Задачи 1–6 решаются в базе `users_db`, задачи 7–24 — в `courses_db`. Сначала накликайте данные в
приложении (пара курсов, уроки, тест, два-три ученика, пройдите уроки под учеником), иначе запросы будут
возвращать пустые таблицы. Решения лежат в [sql/solutions_users_db.sql](sql/solutions_users_db.sql) и
[sql/solutions_courses_db.sql](sql/solutions_courses_db.sql) — подглядывайте только после своей попытки.

Схема таблиц: в DBeaver правой кнопкой по базе → **View Diagram**, или `\d имя_таблицы` в psql.

## Уровень 1 — одна таблица и первые JOIN (`users_db`)

| # | Задача | Что тренируем |
|---|---|---|
| 1 | Выведите всех **активных** пользователей: логин, имя, фамилию, роль и дату регистрации, от самых старых к новым | `SELECT`, `WHERE`, `ORDER BY` |
| 2 | Сколько пользователей каждой роли (`user_type`)? Отсортируйте по убыванию количества | `GROUP BY`, `COUNT` |
| 3 | Кто не заходил больше 7 дней **или не заходил никогда**? Те, кто никогда, — первыми | `IS NULL`, `INTERVAL`, `NULLS FIRST` |
| 4 | Состав каждой группы: название группы, имя и фамилия участника одной строкой, роль, дата добавления | `JOIN` трёх таблиц, конкатенация `\|\|` |
| 5 | Все группы и число участников в каждой. **Пустые группы тоже должны попасть в список** с нулём | `LEFT JOIN`, `COUNT(столбец)` vs `COUNT(*)` |
| 6 | Пользователи, которые **не состоят ни в одной ветке** (branch). Решите двумя способами | `LEFT JOIN ... IS NULL`, `NOT EXISTS` |

## Уровень 2 — статистика по курсам (`courses_db`)

| # | Задача | Что тренируем |
|---|---|---|
| 7 | Курсы с названием категории и ценой. Курсы без категории покажите с текстом «(без категории)». Удалённые курсы (`deleted_at`) не показывать | `LEFT JOIN`, `COALESCE` |
| 8 | Сколько **учеников** (role = `LEARNER`) на каждом курсе, по убыванию. Курсы без учеников — с нулём | `LEFT JOIN`, `COUNT(...) FILTER (WHERE ...)` |
| 9 | По каждому курсу, где есть хоть один ученик: число учеников, средний прогресс (1 знак после запятой), число завершивших | `AVG`, `ROUND`, `HAVING` |
| 10 | Уроки каждого курса по порядку (`position`) и сколько учеников прошёл каждый урок | `JOIN` + `LEFT JOIN`, `GROUP BY` по нескольким столбцам |
| 11 | Суммарное время обучения по каждому курсу в минутах: сумма `completed_at - started_at` по пройденным урокам | арифметика дат, `EXTRACT(EPOCH ...)` |
| 12 | «Сложные» уроки: для каждого урока число начавших, число не завершивших и процент отвала. Только уроки, которые кто-то открывал | `NULLIF`, проценты, `HAVING` |
| 13 | Статистика по тестам: курс, название теста, проходной балл, число отправленных попыток, средний балл, процент сданных | 4 таблицы, `FILTER`, деление без ошибки на ноль |
| 14 | Лучший балл каждого ученика по каждому тесту, число попыток и сдал ли хоть раз | `MAX`, `BOOL_OR` |
| 15 | Состав теста: название теста, номер, тип вопроса, первые 60 символов текста, вес | `LEFT(text, n)`, сортировка по двум столбцам |
| 16 | Выданные сертификаты: номер, курс, название шаблона, пользователь, дата. Шаблон мог быть удалён — сертификат всё равно показать | `LEFT JOIN` |
| 17 | Ученики, которые **завершили курс с шаблоном сертификата, но сертификата не получили** (данные «до» появления сертификатов) | `LEFT JOIN` по двум столбцам, анти-join |

## Уровень 3 — подзапросы, окна, JSON (`courses_db`)

| # | Задача | Что тренируем |
|---|---|---|
| 18 | Рейтинг учеников внутри каждого курса по прогрессу: курс, ученик, прогресс, место | `RANK() OVER (PARTITION BY ... ORDER BY ...)` |
| 19 | Для каждого курса — последний записавшийся ученик и дата записи | CTE (`WITH`), `ROW_NUMBER()` |
| 20 | Для вопросов Multiple choice: текст, число вариантов ответа, число **правильных** вариантов | JSONB: `->`, `->>`, `jsonb_array_length`, `jsonb_array_elements` |
| 21 | Самые сложные вопросы: по всем попыткам посчитайте, сколько раз на каждый вопрос ответили неверно и процент ошибок. Результаты попытки лежат в `test_attempts.results` (массив JSON) | `CROSS JOIN LATERAL jsonb_array_elements`, приведение `::uuid`, `::boolean` |
| 22 | Дерево категорий: каждая категория и её родитель (корневые — с пустым родителем) | self join |
| 23 | Выведите **имена** учеников с их прогрессом по курсам. Имена живут в `users_db`, а прогресс — в `courses_db`. Сначала объясните, почему обычный `JOIN` невозможен, затем решите через расширение `dblink` | `database per service`, `CREATE EXTENSION`, `dblink` |
| 24 | В одной транзакции: добавьте категорию, поднимите цену всех курсов на 10, посмотрите результат и **откатите**. Убедитесь, что данные не изменились | `BEGIN`, `INSERT`, `UPDATE`, `ROLLBACK`, `gen_random_uuid()` |

**Бонус.** Выполните `EXPLAIN ANALYZE` для запроса из задачи 8 и найдите в плане, какой JOIN выбрал
PostgreSQL и сколько строк он прочитал. Добавьте индекс `CREATE INDEX ON enrollments (course_id)` и сравните.

## Как проверять себя

- Результат должен совпадать с тем, что показывает приложение: число учеников — со страницей курса,
  прогресс — с отчётом Users & progress, лучший балл — с экраном теста.
- Если в ответе неожиданно мало строк, проверьте тип JOIN: `INNER` выбрасывает курсы без учеников,
  `LEFT` их оставляет.
- `COUNT(*)` считает строки, `COUNT(столбец)` — только не-NULL значения. В задачах с `LEFT JOIN` это разные числа.
